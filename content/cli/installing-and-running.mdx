## Overview

The Wefter CLI (`@wefterjs/cli`) is designed to be installed as a local **`devDependency`** within your web project (Vue, React, Angular, Svelte, Vite, Next.js, etc.).

Unlike traditional mobile toolchains that require global CLI installations, `@wefterjs/cli` is pinned to your project's `package.json` and lockfile. This ensures identical build behavior across developer machines, CI/CD runners, and automated pipelines without version drift.

<Callout type="info">
  **DevDependency vs Runtime**: `@wefterjs/cli` only executes on your machine or
  CI server during development and build steps. It is never included in your
  compiled web bundle or native app binary. Your application's runtime bridge
  API is provided separately by [`@wefterjs/core`](/docs/core).
</Callout>

## Installation

Install `@wefterjs/cli` into your project's development dependencies using your preferred package manager:

### Using `pnpm` (Recommended)

```bash
pnpm add -D @wefterjs/cli
```

### Using `npm`

```bash
npm install --save-dev @wefterjs/cli
```

### Using `yarn`

```bash
yarn add -D @wefterjs/cli
```

## Binary Resolution & Invocation Methods

When `@wefterjs/cli` is installed, your package manager links the `wefter` executable binary inside your project's `node_modules/.bin/wefter`.

There are two primary methods to invoke the `wefter` command:

### 1. Direct Execution via `npx` / `pnpm exec`

Using `npx wefter` automatically searches your local `node_modules/.bin` directory before falling back to the npm registry. Once installed locally, running `npx wefter` executes your exact pinned version without downloading anything extra:

```bash
npx wefter sync
npx wefter run android --watch
```

For `pnpm` or `yarn` projects:

```bash
pnpm exec wefter sync
# or
yarn wefter sync
```

### 2. NPM Scripts in `package.json` (Recommended for Workflows)

For day-to-day team workflows, declare `wefter` commands inside your project's `package.json` scripts section. Package managers automatically resolve local binaries in `node_modules/.bin` without needing `npx`:

```json
{
  "name": "my-mobile-app",
  "version": "1.0.0",
  "scripts": {
    "dev:android": "wefter run android --watch",
    "dev:ios": "wefter run ios --watch",
    "build:android": "npm run build:web && wefter build android --release --env production",
    "build:ios": "npm run build:web && wefter build ios --release --env production",
    "wefter:sync": "wefter sync"
  }
}
```

Run script commands via your package manager:

```bash
pnpm dev:android
# or
npm run build:android
```

## One-Shot Execution (`npx wefter init`)

If you execute `npx wefter init` in a directory where `@wefterjs/cli` is not yet installed, `npx` prompts to download the package temporarily to run initialization:

```text
Need to install the following packages:
@wefterjs/cli@0.0.3
Ok to proceed? (y)
```

Once `wefter init` completes, `@wefterjs/cli` is automatically declared in your `package.json` under `devDependencies`. Subsequent invocations will use your local pinned package.

## Default (No-Args) & Help Output

Running `wefter` with no arguments displays a summary of available CLI commands, descriptions, and current CLI version:

```bash
wefter
```

To view flag descriptions and usage for any specific command, pass `--help`:

```bash
wefter build --help
wefter run --help
```

---

## Global Installation Avoidance

We strongly recommend **against** installing `@wefterjs/cli` globally (`npm install -g @wefterjs/cli`), except for global build server containers. Local project installation guarantees:

1. **Deterministic Builds**: Every team member uses the exact same CLI version specified in `package.json`.
2. **CI Compatibility**: CI pipelines automatically use lockfile-pinned dependencies without extra environment setup.
3. **No Machine Conflicts**: Different projects on the same machine can use different versions of `@wefterjs/cli` simultaneously.
