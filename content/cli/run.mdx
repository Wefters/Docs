---
title: wefter run
description: Compiles, installs, and launches your app on a physical Android device or iOS Simulator, with optional Vite hot reload.
---

## Synopsis

```bash
wefter run <platform> [--watch] [--env <name>] [--simulator <name>] [projectDir]
```

## Overview & Use Cases

`wefter run` compiles your native application, installs it onto a target device or simulator, and launches it automatically.

When run with `--watch`, it starts a local Vite development server, resolves your LAN IP address, wires network security permissions into the native app, and streams live code changes to your device/simulator with instant hot reload.

### Primary Use Cases

- Iterating on web UI code with live hot reload on a connected Android device or iOS Simulator (`--watch`).
- Testing compiled native binaries in specific environment configurations (e.g. `--env staging`).
- Installing and launching native applications for manual testing.

---

## What It Does

When invoked, `wefter run` executes the following sequence:

1. **Platform & Target Resolution**:
   - For **Android**: Resolves active USB/emulator device via `adb devices`.
   - For **iOS**: Resolves target simulator via `xcrun simctl` (boots simulator if not already running).
2. **Sync Freshness Check**: Verifies `.wefter/sync.marker`. Fails if the project has never been synced or if `wefter.config.json` was modified after the last sync.
3. **Lifecycle Hook (`wefter:run:before`)**: Fires `wefter:run:before` script if declared in `package.json`.
4. **Dev Server Initialization (`--watch`)**:
   - Resolves local LAN IP (`resolveLanIp`).
   - Starts Vite development server (`startDevServer`).
   - Injects network security exception rules and dev server URL into Android `build.gradle.kts` or iOS `BuildConfig.swift`.
5. **Native Build**: Compiles debug native binary via `buildAndroid` or `buildIos`.
6. **Installation & Launch**:
   - **Android**: Executes `adb install -r <apkPath>` and launches `am start -n <appId>/<namespace>.MainActivity`.
   - **iOS**: Executes `xcrun simctl install` and `xcrun simctl launch`.
7. **Lifecycle Hook (`wefter:run:after`)**: Fires `wefter:run:after` script as soon as the app launches.
8. **Hot Reload Watch Loop (`--watch`)**: Listens for SIGINT (`Ctrl+C`) to stop the dev server cleanly.

## Arguments & Options

### Arguments

| Argument     | Type       | Required / Optional | Description                                 | Default                                     |
| ------------ | ---------- | ------------------- | ------------------------------------------- | ------------------------------------------- |
| `<platform>` | Positional | **Required**        | Target native platform: `android` or `ios`. | None (must be specified)                    |
| `projectDir` | Positional | Optional            | Path to project root directory.             | Current working directory (`process.cwd()`) |

### Options (Flags)

| Flag                 | Type    | Description                                                               | Default                          |
| -------------------- | ------- | ------------------------------------------------------------------------- | -------------------------------- |
| `--watch`            | Boolean | Starts a local Vite dev server and enables live hot reload on-device.     | `false`                          |
| `--env <name>`       | String  | Environment to run against (from `environments` in `wefter.config.json`). | `"development"`                  |
| `--simulator <name>` | String  | **iOS only**: `xcrun simctl` device name or UDID to launch on.            | First available iPhone simulator |

## Usage Examples

### Run Android App with Hot Reload

```bash
wefter run android --watch
```

### Run iOS Simulator App with Hot Reload

```bash
wefter run ios --watch
```

### Run Production Environment Build on iOS Simulator

```bash
wefter run ios --env production --simulator "iPhone 15 Pro"
```

## Lifecycle Hooks

`wefter run` supports the following lifecycle hooks declared in your `package.json`:

- **`wefter:run:before`**: Fires after sync freshness check, prior to dev server startup and compilation.
- **`wefter:run:after`**: Fires immediately after the application is installed and launched on the target device/simulator.

## Failure Modes & Error Resolution

| Error Message                                           | Root Cause                                                              | Actionable Resolution                                                                         |
| ------------------------------------------------------- | ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `Unsupported platform "..."`                            | Platform argument was not `android` or `ios`.                           | Run `wefter run android` or `wefter run ios`.                                                 |
| `Project has never been synced. Run wefter sync first.` | Project missing `.wefter/sync.marker`.                                  | Run `wefter sync` before running your app.                                                    |
| `No ADB device connected`                               | No Android device or emulator detected by `adb`.                        | Connect an Android device with USB debugging enabled or launch an emulator in Android Studio. |
| `No simulator found matching "..."`                     | Specified iOS simulator name or UDID does not exist.                    | Run `xcrun simctl list devices` to view available simulator names.                            |
| `adb install -r failed with exit code 1`                | Device installation rejected (e.g. signature mismatch or storage full). | Uninstall existing app from device (`adb uninstall <appId>`) and run `wefter run` again.      |
