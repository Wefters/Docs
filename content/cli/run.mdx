---
title: wefter run
description: Syncs, builds, installs, and launches — optionally with hot reload.
---

## Synopsis

```bash
wefter run <platform> [--watch] [--env <name>] [--simulator <name>] [projectDir]
```

`<platform>` is required, `android` or `ios`, same restriction as
[`wefter build`](/cli/build).

## What it does

Requires the project to already be synced — same sync-freshness check and
refusal as [`wefter build`](/cli/build) if it's missing or stale. `run`
does **not** call `sync` or the `build` command for you; it builds via the
same lower-level Gradle/`xcodebuild` invocation `build` uses, then
installs and launches directly:

- **`android`**: `adb install -r` onto whatever device or emulator is
  currently connected, then `adb shell am start`.
- **`ios`**: resolves a Simulator (see `--simulator` below), boots it if
  it isn't already, then `xcrun simctl install`, then `xcrun simctl
  launch`.

## Options

| Flag                  | Description                                                                                        | Default       |
| ---------------------- | ----------------------------------------------------------------------------------------------------| ------------- |
| `--watch`              | Points the app's WebView at a live local dev server instead of the bundled build, for hot reload.   | off           |
| `--env <name>`         | Which entry under `wefter.config.json`'s `environments` to run.                                     | `development` |
| `--simulator <name>`  | iOS only: the `xcrun simctl` device name or UDID to boot/install/launch on. Ignored for `android`.  | unset — picks the first available simulator whose name starts with `iPhone` |

## Examples

```bash
wefter run android --watch
```

```bash
wefter run ios --watch
```

```bash
wefter run ios --env production
```

Installs and launches a non-watch build of the `production` environment on
the Simulator, useful for checking a production build's real behavior
without a full device release.

## `--watch` behavior, both platforms

Identical hot-reload behavior on Android and iOS: the app's WebView loads
a live Vite dev server instead of bundled assets, edits reflect on-device
without a reinstall, and if the dev server becomes unreachable mid-session
the app shows a clear in-app message rather than a browser-style
connection error or a silent fallback to stale content. Restart `wefter
run --watch` and reload if you see that message. See [Development
Workflow](/docs/development-workflow) for the full day-to-day loop.

## Failure modes

Sync freshness first, the most common reason `run` refuses to start at all:

```
Run failed: Project has never been synced. Run `wefter sync` first.
```

```
Run failed: wefter.config.json has changed since the last `wefter sync`. Run `wefter sync` before building.
```

(That message says "before building" even here — it's the same shared
freshness check `build` uses, word for word.)

An unrecognized `<platform>` fails immediately, before the sync-freshness
check — and isn't prefixed `Run failed:`, it's rejected by the CLI's own
argument handling:

```
Unsupported platform "windows". Use "android" or "ios".
```

Android install/launch failures surface via the underlying `adb` exit code:

```
Run failed: adb install -r /path/to/app.apk failed with exit code 1
```

```
Run failed: adb shell am start -n com.example.app.dev/dev.wefter.bridge.MainActivity failed with exit code 1
```

iOS Simulator resolution and install/launch failures:

```
Run failed: No simulator found matching "iPhone 99". Run `xcrun simctl list devices` to see available simulators.
```

```
Run failed: No available iPhone simulator found. Create one in Xcode (Window > Devices and Simulators) or pass --simulator explicitly.
```

```
Run failed: xcrun simctl launch iPhone 15 com.example.app.dev failed with exit code 1
```

<Callout type="info">
  Like `wefter build`, this targets the Simulator on iOS, not a physical device.
  Device installs are a follow-up capability, not yet covered by this command.
</Callout>
