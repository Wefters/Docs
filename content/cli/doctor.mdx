---
title: wefter doctor
description: Checks your machine is set up to build Wefter apps.
---

## Synopsis

```bash
wefter doctor [--release-readiness] [projectDir]
```

## What it checks

Every check runs regardless of earlier failures, all results are reported
together at the end, not one at a time.

**Always checked, both platforms:**

- Node.js version
- Whether a project's `wefter.config.json` (if present) is valid

**Android checks:**

- `ANDROID_HOME` (or `ANDROID_SDK_ROOT`) is set
- `adb` is reachable on `PATH`
- JDK version (17 required)
- A device or emulator is currently connected

**iOS checks — run every time, on every platform:**

- Running on macOS at all
- Xcode is installed (`xcodebuild -version`)
- Xcode Command Line Tools are installed (`xcode-select -p`)
- At least one Simulator device is available (`xcrun simctl list devices
available`)

Each failing check prints a concrete fix, not just a pass or fail.

<Callout type="warn">
  These four checks run unconditionally, they are **not** skipped on
  Linux/Windows. Off macOS, `checkMacOS` fails, and the three Xcode/Simulator
  checks each short-circuit straight to `passed: false` with `fix: "requires
  macOS"` — a fix you can't actually act on. Since `wefter doctor`'s overall
  pass/fail requires every check to pass, **`wefter doctor` currently always
  exits `1` on a non-macOS machine**, even with a perfectly working
  Android-only setup. There's no "Android-only mode" that silences these yet.
  Treat those four specific lines as expected noise if you're not building
  for iOS, and check the other lines for the real signal.
</Callout>

## `--release-readiness`

Extends the base checks with the release-signing checks for **both**
platforms, unconditionally, not only the platform(s) you've actually
configured signing for:

- **Release security lint** (Android) and **iOS release security lint** —
  runs regardless of signing config; see [`wefter sync`](/cli/sync).
- **Android**: fails on "Signing config" if `wefter.config.json` has no
  `signing` block at all (`keystorePath`, `keyAlias`). If it does, also
  checks the keystore file exists at `keystorePath`, and that
  `WEFTER_KEYSTORE_PASSWORD` is set.
- **iOS**: fails on "iOS signing config" if `wefter.config.json` has no
  `iosSigning` block at all (`teamId`, optional `provisioningProfile`). If
  it does, also checks `WEFTER_IOS_SIGNING_IDENTITY` is set.

```bash
wefter doctor --release-readiness
```

<Callout type="info">
  There's no per-platform opt-out — if you only ship Android and have never
  configured `iosSigning`, `--release-readiness` still reports "iOS signing
  config" as a failure demanding one. `iosSigning.teamId` is a config value,
  not an env var: nothing here reads a `WEFTER_IOS_TEAM_ID` env var, the CLI
  derives it from your config and sets it internally when it shells out to
  `xcodebuild`. The only iOS signing env var you actually set yourself is
  `WEFTER_IOS_SIGNING_IDENTITY`.
</Callout>

Run this before a real release build, not after, so a signing
misconfiguration is caught in seconds rather than after a full Gradle or
`xcodebuild` run fails at the last step.

## Example output

On macOS, with a fully working setup:

```
✔ Node.js version (v20.11.0)
✔ ANDROID_HOME set (/home/you/Android/Sdk)
✔ adb on PATH
✔ JDK version (17.0.9)
✔ Connected device or running emulator (1 device(s))
✔ Running on macOS
✔ Xcode installed (Xcode 15.2)
✔ Xcode Command Line Tools (/Applications/Xcode.app/Contents/Developer)
✔ iOS Simulator available (12 device(s))
```

On Linux/Windows, Android fully working, iOS checks failing as described above:

```
✔ Node.js version (v20.11.0)
✔ ANDROID_HOME set (/home/you/Android/Sdk)
✔ adb on PATH
✔ JDK version (17.0.9)
✔ Connected device or running emulator (1 device(s))
✘ Running on macOS — found linux
    Fix: iOS builds require a Mac (local or CI, e.g. GitHub Actions' macos-latest runner) — the rest of the iOS checks below will also fail until then
✘ Xcode installed
    Fix: requires macOS
✘ Xcode Command Line Tools
    Fix: requires macOS
✘ iOS Simulator available
    Fix: requires macOS
```

That second run still exits `1` (`Some checks failed — see the Fix lines
above.`), even though nothing Android-related is actually wrong.
