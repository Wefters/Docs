## Synopsis

```bash
wefter create-plugin <name> [targetDir]
```

## Overview & Use Cases

`wefter create-plugin` scaffolds a complete, valid, and buildable native plugin package directory.

It creates cross-platform native boilerplate for Android (`Kotlin`) and iOS (`Swift`), along with TypeScript bridge bindings (`src/index.ts`), `plugin.json` manifest, and `package.json`.

### Primary Use Cases

- Authoring custom native capabilities (e.g. bluetooth, biometrics, SQLite, secure storage) for your Wefter applications.
- Initializing a new open-source or private npm plugin package for Wefter.

---

## What It Does

When invoked, `wefter create-plugin` executes the following sequence:

1. **Target Directory Resolution**: Resolves output directory at `<targetDir>/<name>`. Fails if the target folder already exists.
2. **Directory Structure Creation**: Creates `src/`, `android/`, and `ios/` directories.
3. **File Generation**:
   - **`package.json`**: NPM package configuration declaring `@wefterjs/core` dependency.
   - **`plugin.json`**: Plugin manifest declaring permissions, methods, hooks, and events.
   - **`src/index.ts`**: TypeScript wrapper file for calling `invokeNative`.
   - **`android/<PluginName>Plugin.kt`**: Android Kotlin plugin class extending `WefterPlugin` with sample `@WefterMethod`.
   - **`ios/<PluginName>Plugin.swift`**: iOS Swift plugin class extending `WefterPlugin` with sample `// @WefterMethod`.
   - **`README.md`**: Scaffold documentation README.

## Arguments & Options

### Arguments

| Argument    | Type       | Required / Optional | Description                                                                                                             | Default                                     |
| ----------- | ---------- | ------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| `<name>`    | Positional | **Required**        | Plugin package name (e.g. `secure-storage`). Used for directory name and PascalCase class name (`SecureStoragePlugin`). | None (must be specified)                    |
| `targetDir` | Positional | Optional            | Directory to scaffold the plugin folder into.                                                                           | Current working directory (`process.cwd()`) |

### Options (Flags)

`wefter create-plugin` does not accept flags.

## Usage Examples

### Scaffold a New Plugin in Current Directory

```bash
wefter create-plugin secure-storage
```

### Scaffold a Plugin in a Specific Monorepo Directory

```bash
wefter create-plugin barcode-scanner ./packages
```

## Scaffolded File Structure

```text
secure-storage/
├── package.json
├── plugin.json
├── README.md
├── src/
│   └── index.ts
├── android/
│   └── SecureStoragePlugin.kt
└── ios/
    └── SecureStoragePlugin.swift
```

### Android Kotlin Boilerplate (`android/SecureStoragePlugin.kt`)

```kotlin
package dev.wefter.bridge

import android.content.Context
import org.json.JSONObject

class SecureStoragePlugin(context: Context, dispatcher: BridgeDispatcher) : WefterPlugin(context, dispatcher) {
    @WefterMethod
    fun example(payload: JSONObject, callback: (Result<Any>) -> Unit) {
        resolve(callback, JSONObject().put("ok", true))
    }
}
```

<Callout type="warn">
  **Crucial Android Package Rule**: Always retain `package dev.wefter.bridge` at
  the top of Kotlin files. During [`wefter sync`](/cli/sync), Wefter
  automatically replaces this placeholder package name with the host app's real
  namespace. If changed manually, sync will be unable to rewrite the namespace.
</Callout>

### iOS Swift Boilerplate (`ios/SecureStoragePlugin.swift`)

```swift
import Foundation

final class SecureStoragePlugin: WefterPlugin {
    // @WefterMethod
    func example(payload: [String: Any], callback: @escaping (Result<Any, Error>) -> Void) throws {
        resolve(callback, data: ["ok": true])
    }
}
```

## Lifecycle Hooks

`wefter create-plugin` does **not** trigger CLI lifecycle hooks.

---

## Failure Modes & Error Resolution

| Error Message           | Root Cause                                      | Actionable Resolution                                             |
| ----------------------- | ----------------------------------------------- | ----------------------------------------------------------------- |
| `<path> already exists` | Target plugin directory already exists on disk. | Specify a different plugin name or remove the existing directory. |
