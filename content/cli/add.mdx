title: wefter add
description: Looks up an npm plugin package on the registry, records the resolved version in package.json, and declares it in wefter.config.json — without running any install command.
---

## Synopsis

```bash
wefter add <plugin> [projectDir]
```

## Overview & Use Cases

`wefter add` registers a Wefter native plugin in your project **without running any package-manager install command**. It fetches the package metadata (name, resolved version, description) directly from the npm registry, adds the dependency to `package.json`, and appends the plugin name to the `plugins` array in `wefter.config.json`.

Because no install is executed, `wefter add` works identically regardless of whether your project uses **npm, pnpm, yarn, or bun**. After running it, the CLI tells you the exact command to install the package with whichever manager you are using.

### Primary Use Cases

- Quickly declaring a native capability plugin (camera, biometrics, secure storage, …) in your Wefter project.
- Keeping `wefter.config.json` and `package.json` in sync without touching your lockfile or node\_modules.

---

## What It Does

When invoked, `wefter add` executes the following sequence:

1. **Config Validation**: Validates `wefter.config.json` in `projectDir`. Halts if project configuration is invalid.
2. **Package Spec Check**: Verifies `<plugin>` matches valid npm package naming syntax (`name`, `name@version`, or `name@dist-tag`).
3. **Duplicate Check**: If the plugin is already declared in `wefter.config.json`, logs a warning and exits cleanly without modifying any files.
4. **Registry Fetch**: Calls the npm registry (`registry.npmjs.org`) to resolve the package name and latest (or pinned) version. Fails fast with a clear error if the package is not found.
5. **`package.json` Update**: Adds `"<name>": "^<version>"` to the `dependencies` field of the project's `package.json` (if one exists and does not already pin the package).
6. **`wefter.config.json` Update**: Appends the plugin package name to the `plugins` array.
7. **Install Hint**: Detects which package manager you are using from your lockfile and prints the exact command to run.

<Callout type="info">
  **No install is run.** `wefter add` never calls `npm install`, `pnpm add`, `yarn add`, or `bun add`. The actual installation is left entirely to you, so your lockfile and workspace policies are never bypassed.
</Callout>

<Callout type="info">
  **No local validation yet.** Because the package has not been installed yet, native plugin validation (schema, annotations, source checks) is deferred to `wefter sync`, which runs the full validation pass once the package is actually present in `node_modules`.
</Callout>

## Package Manager Detection

`wefter add` detects your package manager from lockfile presence in `projectDir`:

| Lockfile found         | Install hint shown          |
| ---------------------- | --------------------------- |
| `pnpm-lock.yaml`       | `pnpm add <name>@<version>` |
| `yarn.lock`            | `yarn add <name>@<version>` |
| `bun.lockb` / `bun.lock` | `bun add <name>@<version>` |
| _(none of the above)_  | `npm install <name>@<version>` |

The hint is informational only — nothing is executed automatically.

## Arguments & Options

### Arguments

| Argument     | Type       | Required / Optional | Description                                                                                      | Default                                     |
| ------------ | ---------- | ------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------- |
| `<plugin>`   | Positional | **Required**        | npm package specifier (`name`, `name@version`, or `name@tag`, e.g. `@wefterjs/camera@1.2.0`).   | None (must be specified)                    |
| `projectDir` | Positional | Optional            | Path to project root directory.                                                                  | Current working directory (`process.cwd()`) |

### Options (Flags)

`wefter add` does not accept flags.

---

## Usage Examples

### Adding a Scoped Plugin (latest version)

```bash
wefter add @wefterjs/camera
```

### Pinning a Specific Version

```bash
wefter add my-custom-plugin@1.2.0
```

### Adding a Plugin to a Specific Workspace Directory

```bash
wefter add @wefterjs/device ./apps/mobile-app
```

## Execution Output

### Success

```text
[SUCCESS] Added @wefterjs/camera@0.1.0 to wefter.config.json.
[INFO] Now install it with your package manager:
[INFO]   pnpm add @wefterjs/camera@0.1.0
[INFO] Then run `wefter sync` to weave it into the native project.
```

### Already Declared

```text
[WARN] @wefterjs/camera is already declared in wefter.config.json — nothing to add.
```

---

## Recommended Workflow

```bash
# 1. Declare the plugin (fetches version, updates config & package.json)
wefter add @wefterjs/camera

# 2. Install with your package manager (command shown by step 1)
pnpm add @wefterjs/camera@0.1.0

# 3. Weave into native project (runs full validation at this point)
wefter sync
```

---

## Lifecycle Hooks

`wefter add` does **not** trigger CLI lifecycle hooks.

---

## Failure Modes & Error Resolution

| Error Message                                         | Root Cause                                               | Actionable Resolution                                                                  |
| ----------------------------------------------------- | -------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `"<spec>" doesn't look like a valid npm package name` | Specifier format is invalid.                             | Pass a valid npm package name or `package@version`.                                    |
| `<plugin> is already declared in wefter.config.json`  | Plugin name is already in `plugins` array.               | No action required (or run `wefter sync` to refresh native dependencies).              |
| `Package "<spec>" was not found on the npm registry`  | Package does not exist or is not yet published.          | Check the package name spelling or publish the package first.                          |
| `npm registry returned HTTP <N> for "<spec>"`         | Registry returned an unexpected error (auth, rate-limit).| Check network access, npm auth tokens, or private registry configuration.              |
