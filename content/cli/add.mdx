---
title: wefter add
description: Installs an npm plugin package, validates native code integrity, audits permissions/conflicts, and declares it in wefter.config.json.
---

## Synopsis

```bash
wefter add <plugin> [projectDir]
```

## Overview & Use Cases

`wefter add` installs an npm package containing a Wefter native plugin, validates its directory structure and native signatures, checks for security or version conflicts, and appends the plugin package name to `wefter.config.json`.

It acts as a **validation gate**: if the installed npm package fails native validation (e.g. malformed native annotations or missing native code), `wefter add` refuses to declare it in `wefter.config.json`.

### Primary Use Cases

- Adding a native capability plugin (e.g. camera, geolocation, secure storage) to your Wefter app.
- Safely validating third-party plugin packages before declaring them in your project configuration.

---

## What It Does

When invoked, `wefter add` executes the following sequence:

1. **Config Validation**: Validates `wefter.config.json` in `projectDir`. Halts if project configuration is invalid.
2. **Package Specification Check**: Verifies `<plugin>` matches valid npm package naming syntax (`name` or `name@version`).
3. **Check Pre-existing Declaration**: If the plugin is already declared in `wefter.config.json`, logs a warning and exits cleanly without modifying files.
4. **NPM Package Installation**: Runs package installation (`npm install <plugin>`) inside `projectDir`.
5. **Native Plugin Validation (`pluginValidate`)**:
   - Verifies `plugin.json` matches schema.
   - Verifies native source directory (`android/` or `ios/`) exists.
   - Audits Kotlin (`@WefterMethod`/`@WefterHook`) and Swift signatures against declared `plugin.json` method lists.
6. **Config Update**: Appends plugin package name to `plugins` array in `wefter.config.json`.
7. **Audit Warnings Output**: Logs warnings if the newly added plugin exports Android manifest components, requires missing `pluginConfig` keys, or has Gradle dependency version conflicts.

<Callout type="warn">
  **Validation Gate**: If a plugin fails validation during step 5, `wefter add`
  leaves `wefter.config.json` completely untouched. Unvalidated plugins can
  never be silently woven into your native project by `wefter sync`.
</Callout>

## Arguments & Options

### Arguments

| Argument     | Type       | Required / Optional | Description                                                                                     | Default                                     |
| ------------ | ---------- | ------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------- |
| `<plugin>`   | Positional | **Required**        | npm package specifier (`name` or `name@version`, e.g. `@wefterjs/camera` or `my-plugin@1.2.0`). | None (must be specified)                    |
| `projectDir` | Positional | Optional            | Path to project root directory.                                                                 | Current working directory (`process.cwd()`) |

### Options (Flags)

`wefter add` does not accept flags.

---

## Usage Examples

### Installing a Scoped Plugin

```bash
wefter add @wefterjs/camera
```

### Installing a Specific Version of a Plugin

```bash
wefter add my-custom-plugin@1.2.0
```

### Adding a Plugin to a Specific Workspace Directory

```bash
wefter add @wefterjs/device ./apps/mobile-app
```

---

## Execution Output & Log Indicators

### Success Output

```text
[SUCCESS] Validated and added @wefterjs/camera to wefter.config.json.
[INFO] Run `wefter sync` to weave it into the native project.
```

### Success Output with Warnings (Exported Components / Missing Config Keys)

```text
[SUCCESS] Validated and added @wefterjs/auth to wefter.config.json.
[WARN] Declares exported component(s), reachable from outside the app: activity .AuthRedirectActivity
[WARN] Requires "pluginConfig" key(s) not yet set in wefter.config.json: authDomain
[INFO] Run `wefter sync` to weave it into the native project.
```

---

## Lifecycle Hooks

`wefter add` does **not** trigger CLI lifecycle hooks.

---

## Failure Modes & Error Resolution

| Error Message                                           | Root Cause                                                     | Actionable Resolution                                                                  |
| ------------------------------------------------------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `"<spec>" doesn't look like a valid npm package name`   | Specifier format is invalid.                                   | Pass a valid npm package name or `package@version`.                                    |
| `<plugin> is already declared in wefter.config.json`    | Plugin name is already in `plugins` array.                     | No action required (or run `wefter sync` to refresh native dependencies).              |
| `<plugin> failed validation and will NOT be added: ...` | Installed package failed native schema or annotation checks.   | Fix plugin source/manifest or choose a compliant plugin version.                       |
| `npm install failed with exit code ...`                 | npm registry error or network failure during package download. | Check internet connection, package name spelling, or private npm registry credentials. |
