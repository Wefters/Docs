---
title: wefter audit
description: Read-only, what it prints, and what it never touches.
---

```bash
wefter audit [projectDir]
```

| Argument | Type | Default | Purpose |
| --- | --- | --- | --- |
| `projectDir` | positional, optional | current working directory | Project root. |

Resolves declared plugins from `wefter.config.json` and reports exactly
what the next [`wefter sync`](/cli/sync) would weave in, without writing
anything. No `wefter.lock.json` update, no native project regeneration, no
`wefter.config.json` change. Safe to run anytime, including in CI as a
pre-merge check.

<Callout type="warn">
  `audit` currently only reports the Android side: `permissions.android`,
  `nativeDependencies.android.gradle`, and `android.manifestEntries`. It
  doesn't yet surface a plugin's `permissions.ios` or
  `nativeDependencies.ios.spm`, even though [`wefter sync`](/cli/sync) does
  weave both in for iOS. If you need to see what a plugin declares for iOS
  before it's woven in, read its `plugin.json` directly for now.
</Callout>

## What it prints

**Every resolved plugin**, with its declared permissions, every Gradle
dependency, and any declared components:

```
Plugins (2):
  storage — permissions: none
  scanner — permissions: android.permission.CAMERA, gradle: androidx.camera:camera-camera2:1.6.1, com.google.mlkit:barcode-scanning:17.3.0
    component: activity .BrowserAuthActivity (exported)
```

**Declared but not installed**: plugin names in `config.plugins` with no
matching package found under `config.pluginsDir`:

```
Declared but not installed: @wefterjs/plugin-missing
```

**Exported components**: a category distinct from permissions — an
exported activity with an intent-filter is reachable from *outside* the
app, a materially different risk than "this plugin can read the camera":

```
Exported components (reachable from outside the app):
  - browser: declares an exported activity (.BrowserAuthActivity) — reachable from outside the app.
```

**Gradle dependency version conflicts**: when two installed plugins
declare the same `group:artifact` at different *major* versions. Wefter
still resolves to the highest version so `sync` doesn't fail outright,
but a silent runtime surprise here is exactly what this warning exists to
prevent:

```
Gradle dependency version conflicts:
  - androidx.camera:camera-core: declared at different major versions across plugins (scanner@1.3.0, camera@2.0.0) — highest version wins.
```

**Required `pluginConfig` keys**: placeholders (`${key}`) referenced by a
plugin's `android.manifestEntries` that `wefter.config.json`'s
`pluginConfig` doesn't yet set — `sync` will fail on these, so `audit`
surfaces them ahead of time:

```
Required "pluginConfig" keys not yet set: appScheme
```

**Permission audit violations**: the same sensitive-API check `sync` runs
(a plugin's Kotlin source uses `CameraX` or `LocationManager` without
declaring the matching permission in `plugin.json`):

```
Permission audit violations:
  - scanner: uses CameraX but does not declare android.permission.CAMERA in plugin.json
```

**Lockfile drift**: the same comparison covered on [wefter.lock.json's
role](/cli/lockfile-role), between each resolved plugin's installed
version and what's recorded in `wefter.lock.json`:

```
Lockfile drift:
  - storage: locked at 0.0.1, found 0.1.0
```

## Reports instead of blocking

This is the key difference from `sync`: where a permission violation or
lockfile drift *fails* `wefter sync`, `audit` only reports them and still
exits `0`. It's a look-before-you-sync command, not a gate: useful for
seeing what a `sync` would object to without actually running it (and
without needing `--update-lock` to get past drift just to inspect
plugins). Gradle conflicts and missing `pluginConfig` keys are warnings
here too — `sync` still weaves and resolves to the highest version rather
than failing on a conflict, and only fails outright on a placeholder it
genuinely can't resolve.

## Exit codes

`0` on a completed audit, regardless of what it found. `1` only if the
audit itself couldn't run (e.g. an invalid `wefter.config.json`):

```
Audit failed: <reason>
```
