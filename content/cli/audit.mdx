## Synopsis

```bash
wefter audit [projectDir]
```

## Overview & Use Cases

`wefter audit` is a **read-only, non-destructive** command that inspects your declared native plugins in `wefter.config.json` and outputs a comprehensive analysis of permissions, dependencies, exported Android components, required plugin configuration keys, and lockfile drift.

It performs zero filesystem writes: it does not update `wefter.lock.json`, modify `wefter.config.json`, or touch `.wefter/native/`. It is ideal for pre-merge CI checks, security reviews, and inspecting native impact before running `wefter sync`.

### Primary Use Cases

- Performing a security audit of native permissions and exported manifest components.
- Inspecting Gradle dependency major-version conflicts between installed plugins.
- Identifying missing `pluginConfig` keys referenced by plugin manifest placeholders.
- Verifying lockfile drift between `node_modules` and `wefter.lock.json` in CI pipelines.

---

## What It Does

When invoked, `wefter audit` performs the following analysis:

1. **Loads Project Configuration**: Loads and validates `wefter.config.json` in `projectDir`.
2. **Resolves Plugins**: Resolves each plugin in `config.plugins` from `node_modules`. Reports uninstalled declared plugins.
3. **Audits Permissions & Sensitive APIs**: Scans Kotlin sources for sensitive Android API usage (`CameraX`, `LocationManager`) and flags code using sensitive APIs without declared permissions.
4. **Inspects Exported Components**: Scans manifest entries for components with `exported: true` (components reachable from outside the app via deep links or IPC).
5. **Checks Gradle Version Conflicts**: Identifies major-version conflicts across plugin Gradle dependencies (e.g. `camera-core` version mismatch).
6. **Validates Configuration Placeholders**: Identifies `${placeholder}` variables in manifest templates that are missing matching keys in `config.pluginConfig`.
7. **Detects Lockfile Drift**: Compares installed plugin package versions against entries in `wefter.lock.json`.

## Arguments & Options

### Arguments

| Argument     | Type       | Required / Optional | Description                     | Default                                     |
| ------------ | ---------- | ------------------- | ------------------------------- | ------------------------------------------- |
| `projectDir` | Positional | Optional            | Path to project root directory. | Current working directory (`process.cwd()`) |

### Options (Flags)

`wefter audit` does not accept flags.

`wefter audit` does **not** trigger CLI lifecycle hooks.

## Failure Modes & Error Resolution

| Error Message                                | Root Cause                                                                       | Actionable Resolution                                                               |
| -------------------------------------------- | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `Audit failed: wefter.config.json not found` | Command executed outside a valid Wefter project directory.                       | Run `wefter init` or navigate to project directory containing `wefter.config.json`. |
| `Audit failed: Invalid config: ...`          | `wefter.config.json` fails schema validation.                                    | Fix schema formatting errors in `wefter.config.json`.                               |
| `Declared but not installed: <plugin>`       | Plugin listed in `config.plugins` is not installed in `node_modules`.            | Run `pnpm install` or `npm install` to install missing plugin package.              |
| `Permission audit violations: <plugin>`      | Plugin source uses sensitive APIs without declared permissions in `plugin.json`. | Contact plugin author or add missing permission to plugin manifest.                 |
| `Lockfile drift: <plugin>`                   | Plugin version in `node_modules` differs from `wefter.lock.json`.                | Run `wefter sync --update-lock` to sync and re-lock plugin versions.                |
