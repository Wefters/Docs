---
title: wefter icon generate
description: Standalone icon preview, and the "lost on next sync" caveat.
---

```bash
wefter icon generate <source> [projectDir]
```

| Argument | Type | Purpose |
| --- | --- | --- |
| `source` | positional, required | Path to a source image, relative to `projectDir`. Must be at least 1024x1024px: fails with `Icon source is <w>x<h>px, but must be at least 1024x1024px: <resolved path>` if smaller. Fails with `Icon source not found: <resolved path>` if it doesn't exist. |
| `projectDir` | positional, optional, default current working directory | Project root. |

```bash
wefter icon generate ./my-logo.png
```

## What it generates

Resizes the source image to five Android launcher icon densities, writing
both the legacy `ic_launcher.png` and the adaptive icon foreground layer
`ic_launcher_foreground.png`, plus the `mipmap-anydpi-v26` adaptive icon
XML and a background color sampled from the source image:

| Density | Legacy size | Adaptive foreground size |
| --- | --- | --- |
| `mdpi` | 48px | 108px |
| `hdpi` | 72px | 162px |
| `xhdpi` | 96px | 216px |
| `xxhdpi` | 144px | 324px |
| `xxxhdpi` | 192px | 432px |

Full context on this on the Docs tab's [App Icon](/docs/app-icon) page.

<Callout type="info">
  This standalone command is Android-only. It does not touch
  `.wefter/native/ios/.../Assets.xcassets`. Setting `icon` in
  `wefter.config.json` and running [`wefter sync`](/cli/sync) instead
  generates icons for **both** platforms. This command exists purely for
  a quick before-you-commit-to-config preview on Android, not as the iOS
  equivalent of anything.
</Callout>

## Standalone means it writes straight into the current native project

Unlike setting `icon` in `wefter.config.json`, this command writes
directly into the *current* generated (or ejected) native project's
resource directory immediately. It does not read or write
`wefter.config.json`, and it runs entirely independent of
[`wefter sync`](/cli/sync).

## Lost on the next `wefter sync`, unless config says otherwise

Because `sync` regenerates the native shell from scratch, running this
command as a one-off preview means the icons it wrote are gone the moment
you next run `wefter sync`, unless `icon` is also set in
`wefter.config.json`, in which case `sync` regenerates the same files
from that source itself, every time, and this command becomes redundant
for anything but a quick before-you-commit-to-config look:

```json
{ "icon": "./resources/icon.png" }
```

Use `wefter icon generate` to preview quickly on a device without editing
config yet; set `icon` in config once you're happy with the source image,
so it survives every future sync automatically.
