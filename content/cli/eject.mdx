---
title: wefter eject
description: Transfers full ownership of native Android and iOS project shells to your project root (android/ and ios/).
---

## Synopsis

```bash
wefter eject [projectDir]
```

## Overview & Use Cases

`wefter eject` copies the generated native project shells (`.wefter/native/android` and `.wefter/native/ios`) directly into `android/` and `ios/` at your project root.

Once ejected, Wefter permanently hands 100% native project ownership to you. `wefter sync` will no longer wipe or recreate the native project shells from templates, allowing you to open `android/` in Android Studio and `ios/` in Xcode for custom native development.

### Primary Use Cases

- Adding custom native Kotlin/Swift code directly to your application without writing a separate plugin package.
- Modifying complex native Android Gradle build scripts, iOS Xcode targets, or third-party native SDK integrations.
- Integrating native push notification handlers, deep link routers, or custom native UI views.

<Callout type="warn">
  **One-Way Operation**: `wefter eject` is a one-way operation. There is no `wefter un-eject` command. Once ejected,
  `wefter sync`, `wefter build`, and `wefter run` will permanently operate against your root `android/` and `ios/`
  folders.
</Callout>

---

## What It Does

When invoked, `wefter eject` executes the following sequence:

1. **Ejection Check**: Verifies project has not already been ejected (checks for `.wefter-ejected` file).
2. **Freshness Sync**: Executes `wefter sync` to ensure `.wefter/native/` files are up-to-date with current configuration and plugins.
3. **Shell Copying**: Copies `.wefter/native/android` to `<projectDir>/android` and `.wefter/native/ios` to `<projectDir>/ios`.
4. **Marker Generation**: Writes `.wefter-ejected` marker file containing `true` at project root.
5. **Path Resolution Update**: All subsequent Wefter CLI commands (`sync`, `build`, `run`) automatically switch path resolution to target root `android/` and `ios/` directories.

---

## What Continues Working Post-Eject

Ejecting does **not** mean losing CLI sync capabilities:

- **Plugin Source Weaving**: `wefter sync` continues to weave native plugin source files into `android/` and `ios/`.
- **Dependency & Permission Merging**: `wefter sync` continues to merge Gradle dependencies, SPM packages, Android permissions, and iOS `Info.plist` keys.
- **Bridge Registries**: `wefter sync` continues to regenerate `WefterPluginRegistry.kt` and `WefterPluginRegistry.swift`.
- **Build & Run Commands**: `wefter build` and `wefter run` continue to compile, install, and run your app using your hand-edited `android/` and `ios/` projects.

## Arguments & Options

### Arguments

| Argument     | Type       | Required / Optional | Description                     | Default                                     |
| ------------ | ---------- | ------------------- | ------------------------------- | ------------------------------------------- |
| `projectDir` | Positional | Optional            | Path to project root directory. | Current working directory (`process.cwd()`) |

### Options (Flags)

`wefter eject` does not accept flags.

---

## Usage Examples

### Eject Native Projects in Current Directory

```bash
wefter eject
```

### Eject Native Projects in a Specific Directory

```bash
wefter eject ./apps/mobile-app
```

---

## Execution Output & Log Indicators

```text
[SUCCESS] Ejected. /path/to/project/android, /path/to/project/ios are now yours — wefter will no longer regenerate them automatically.
```

---

## Lifecycle Hooks

`wefter eject` does **not** trigger CLI lifecycle hooks.

---

## Failure Modes & Error Resolution

| Error Message                                            | Root Cause                                                     | Actionable Resolution                                                                              |
| -------------------------------------------------------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `Already ejected — android/ and ios/ are already yours.` | Project has already been ejected.                              | Edit `android/` or `ios/` folders directly; `wefter sync` will continue to update plugin bindings. |
| `Sync failed: ...`                                       | Pre-eject sync failed due to invalid config or lockfile drift. | Fix sync error (e.g. run `wefter sync --update-lock`) before ejecting.                             |
