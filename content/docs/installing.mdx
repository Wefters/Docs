## Overview

Wefter attaches to an existing web application project (Vue, React, Angular, Svelte, or Vanilla JS with Vite/Webpack).

It does not overwrite your web source code; instead, it generates a configuration manifest (`wefter.config.json`), appends pinned dependency packages, and sets environment variables.

---

## 1. Run `wefter init`

Navigate to your web application's root directory (where `package.json` resides) and run:

```bash
npx wefter init
```

### Interactive Initialization Prompts

`wefter init` prompts for three configuration settings (pre-filled with defaults inferred from `package.json`):

1. **App ID (reverse-DNS format)**: e.g. `dev.local.myapp` (or `com.company.app`).
2. **App Name**: Human-readable application title (e.g. `My Application`).
3. **Web Build Directory**: Output folder produced by your web bundler (e.g. `dist` or `build`).

```text
? App ID (reverse-DNS) (dev.local.myapp) › dev.company.myapp
? App name (Myapp) › MobileApp
? Web build output directory (dist) › dist
```

---

## What `wefter init` Modifies

Executing `wefter init` performs the following automated setup steps:

1. **Generates `wefter.config.json`**:
   ```json
   {
     "webDir": "dist",
     "environments": {
       "development": {
         "appId": "dev.company.myapp",
         "appName": "MobileApp"
       }
     },
     "plugins": []
   }
   ```
2. **Pins Dependencies in `package.json`**:
   - Appends `"@wefterjs/core": "<CLI_VERSION>"` to `dependencies`.
   - Appends `"@wefterjs/cli": "<CLI_VERSION>"` to `devDependencies`.
   - _Note_: `wefter init` does **not** auto-run package installation, giving developers full control over package managers (`pnpm install`, `npm install`, `yarn`).
3. **Writes Environment Variables (`.env`)**:
   - Appends `WEFTER_APP_ID`, `WEFTER_APP_NAME`, and `WEFTER_WEB_DIR` to `.env`.

---

## 2. Install Dependencies

Install the updated dependencies using your preferred package manager:

```bash
pnpm install
# or npm install / yarn
```

---

## 3. Sync Native Projects

Run [`wefter sync`](/cli/sync) to compile configuration into native project shells:

```bash
wefter sync
```

`wefter sync` generates disposable native projects inside `.wefter/native/android` and `.wefter/native/ios`, merges web assets, and builds native bridge dispatchers.

---

## 4. Launch Development Hot Reload

Start a hot-reloading development session on a connected device or emulator:

```bash
# Android ADB device / emulator
wefter run android --watch

# iOS Simulator (macOS)
wefter run ios --watch
```

With `--watch`, Wefter routes the native WebView to your web dev server, delivering sub-second hot module replacement (HMR) directly on mobile devices.
