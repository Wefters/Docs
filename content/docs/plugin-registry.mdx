## Overview

The Wefter plugin architecture connects npm JavaScript packages (`src/index.ts`) with native source files (`android/*.kt` and `ios/*.swift`).

Native plugins are integrated into host projects exclusively via explicit declaration in `wefter.config.json`'s `plugins` array.

---

## 1. Explicit Declaration (No Implicit Auto-Discovery)

Wefter deliberately omits auto-discovery of packages in `node_modules`.

A package installed in `node_modules` (even if directly imported by web JS) contributes **zero native code, zero Android permissions, and zero Gradle/SPM dependencies** unless its name is explicitly declared in `wefter.config.json`:

```json
{
  "plugins": ["@wefterjs/camera", "@wefterjs/storage"]
}
```

This explicit design prevents third-party transitive npm dependencies from silently injecting unreviewed native permissions or native source files into your mobile application.

---

## 2. The `wefter sync` Weaving Pipeline

When [`wefter sync`](/cli/sync) runs, it executes a 5-step native weaving pipeline for every declared plugin:

<Steps>
  <Step>
    ### 1. Package Resolution Resolves declared plugin packages from `pluginsDir` (defaults to `node_modules`).
  </Step>
  <Step>
    ### 2. Lockfile Integrity Audit Cross-checks resolved plugin versions and native file hashes against
    `wefter.lock.json`.
  </Step>
  <Step>
    ### 3. Native Method & Hook Signature Audit Audits `@WefterMethod` and `@WefterHook` annotations against method
    declarations in `plugin.json`.
  </Step>
  <Step>
    ### 4. Native Manifest & Dependency Injection Merges Gradle Maven dependencies into `build.gradle.kts`, SPM packages
    into `Package.swift`, ProGuard rules, Android permissions, and `Info.plist` usage descriptions.
  </Step>
  <Step>
    ### 5. Static Registry Codegen Generates static, zero-reflection Kotlin (`GeneratedRegistry.kt`) and Swift
    (`GeneratedRegistry.swift`) dispatchers.
  </Step>
</Steps>

1. **Resolution**: Resolves plugin directories from `pluginsDir` (defaults to `node_modules`).
2. **Lockfile Audit**: Cross-checks resolved plugin version and file hashes against `wefter.lock.json`.
3. **Signature Audit**: Audits Kotlin (`@WefterMethod`) and Swift (`// @WefterMethod`) method signatures against method declarations in `plugin.json`.
4. **Native Manifest & Dependency Merging**:
   - **Android**: Merges permissions into `AndroidManifest.xml`, Gradle Maven coordinates into `build.gradle.kts`, ProGuard rules into `proguard-rules.pro`, and Activities into the manifest.
   - **iOS**: Merges usage description keys into `Info.plist` and Swift Package Manager (SPM) coordinates into `Package.swift`.
5. **Registry Generation**: Generates static `GeneratedRegistry.kt` and `GeneratedRegistry.swift` files mapping plugin IDs directly to native plugin class instances.

## 3. Global Plugin Access: `WefterBridge`

Every registered native plugin instance is accessible globally across native code via `WefterBridge`:

### Android (Kotlin)

```kotlin
val plugin = WefterBridge.getPlugin("camera") as? CameraPlugin
```

### iOS (Swift)

```swift
if let plugin = WefterBridge.plugin(withId: "camera") as? CameraPlugin {
    // Access native plugin instance
}
```

## 4. Deterministic Lockfile: `wefter.lock.json`

`wefter.lock.json` tracks exact plugin versions and SHA-256 content integrity hashes across `plugin.json` and native source files:

```json
{
  "plugins": {
    "@wefterjs/camera": {
      "resolved": "1.0.0",
      "integrity": "sha256-b74045472a2336e36fe54a6c9310507e5968064b597a269d963fbd296ebb2403"
    }
  },
  "syncedAt": "2026-08-14T10:00:00.000Z"
}
```

If an installed plugin's version or native source changes without updating `wefter.lock.json`, `wefter sync` halts with an integrity drift error.

To accept intentional version updates and recalculate hashes, pass `--update-lock`:

```bash
wefter sync --update-lock
```
