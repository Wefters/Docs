---
title: Plugin Registry
description: How native plugins get woven into your app, and why nothing is auto-discovered.
---

A Wefter plugin pairs a JS package (what your web app imports) with native
source for whichever platform(s) it supports (`android/*.kt`, `ios/*.swift`,
or both). `wefter sync` is what fuses these into your generated native
project, for both platforms.

## Explicit only, no auto-detection

`sync` reads exactly the `plugins` array in `wefter.config.json` and
resolves each entry from `node_modules`. It never scans `node_modules`
looking for anything that looks like a plugin.

A package sitting in `node_modules`, even one your web app directly
imports, contributes zero native code, permissions, or dependencies unless
its name is explicitly listed in `plugins`. This keeps a transitive
dependency from silently gaining a native footprint in your app just
because it happens to be installed somewhere in your tree.

```json
{
  "plugins": ["@yourorg/scanner-plugin", "@yourorg/storage-plugin"]
}
```

## Platform support is per-plugin, not all-or-nothing

A plugin only needs to ship native source for the platform(s) it actually
supports:

```
plugins/scanner/
├── plugin.json
├── src/index.ts
├── android/ScannerPlugin.kt   ← optional
└── ios/ScannerPlugin.swift     ← optional, at least one of the two required
```

`sync` weaves in whichever platform folders each plugin ships, into both
the Android and iOS projects it generates. A plugin declaring only
`android/` still works fine in an Android-only project; calling that
plugin's method from an iOS build it doesn't implement rejects with a
clear `UNKNOWN_PLUGIN` error rather than silently doing nothing.

## What `sync` actually does

For each declared plugin, `sync`:

1. Resolves the package directory and reads `plugin.json`.
2. Verifies the package against `wefter.lock.json` (see below).
3. Scans the plugin's native source for method/hook markers (`@WefterMethod`
   annotations on Android, `// @WefterMethod` comments on iOS) and
   cross-checks them against `plugin.json`'s declared `methods`/`hooks`. A
   mismatch fails the sync loudly.
4. Regenerates the native project's plugin registry from scratch, for
   both platforms.

`sync` is not incremental or additive. Every run rebuilds the generated
registry from your current config, for every platform, so there's no
persistent state that can drift from what's actually declared.

## `wefter add`

```bash
wefter add @yourorg/some-plugin
```

Installs the package, validates it against every platform it declares
support for, and declares it in `wefter.config.json`, all or nothing. If
validation fails on any platform the plugin claims to support, the package
is still installed on disk but `wefter.config.json` is left untouched, so
a bad plugin never silently becomes part of your app.

## `wefter.lock.json`

```json
{
  "plugins": {
    "scanner": {
      "resolved": "0.0.1",
      "integrity": "sha256-b74045472a2336e36fe54a6c9310507e5968064b597a269d963fbd296ebb2403"
    }
  },
  "syncedAt": "2026-08-07T09:44:05.704Z"
}
```

The `integrity` hash covers a plugin's `plugin.json`, its resolved version,
and every native source file across whichever platforms it supports (both
`android/*.kt` and `ios/*.swift`, if both are present), sorted by filename.
A plugin adding iOS support to an existing Android-only implementation
produces a new integrity hash, since real source changed, even if the
declared version string didn't, exactly the "integrity changed but
resolved didn't" case worth double-checking when reading a diff.

Records the exact resolved version and content hash of every synced
plugin, and is meant to be committed to version control. `sync` fails if a
plugin's installed version no longer matches its lock entry (the
`integrity` hash is recorded for you to check by hand, not compared
automatically). Pass `--update-lock` to intentionally accept the drift and
re-lock.

Plugin-authoring depth, the native base classes, method/hook annotations,
and `plugin.json`'s full schema for both platforms, lives on the
[Plugin tab](/plugin).
