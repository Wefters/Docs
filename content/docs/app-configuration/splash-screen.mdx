## Overview

Wefter supports rich, custom HTML-based splash screens. Rather than displaying static raster images that stretch awkwardly across diverse screen aspect ratios, Wefter launches a dedicated native WebView rendering developer-authored HTML, CSS, and SVG assets.

The splash screen is **disabled by default** (`"splash": false`).

---

## Schema Reference

| Property | Type | Required / Optional | Default | Description |
| --- | --- | --- | --- | --- |
| `source` | String | **Required** | None | Relative path to directory containing custom splash `index.html` and assets. |
| `minDuration` | Number (ms) | Optional | `0` | Minimum display duration in milliseconds (0 to 20,000ms). Prevents UI flickering on ultra-fast devices. |
| `maxDuration` | Number (ms) | Optional | `5000` | Safety timeout cap in milliseconds (0 to 20,000ms). Automatically dismisses the splash if the app fails to load. |
| `dismissOn` | String | Optional | `"ready"` | Dismissal trigger: `"ready"` (waits for programmatic `hideSplash()` call) or `"timer"` (dismisses when `minDuration` expires). |
| `transition` | String | Optional | `"fade"` | Transition animation when dismissed: `"fade"` or `"none"`. |

```json
{
  "splash": {
    "source": "./resources/splash",
    "minDuration": 400,
    "maxDuration": 5000,
    "dismissOn": "ready",
    "transition": "fade"
  }
}
```

## The 2-Stage Splash Loading Model

To deliver instant visual feedback without white flashes, Wefter uses a 2-stage splash lifecycle:

```
[Icon Tapped]
     │
     ▼
[Stage 1: Native OS Launch Background]
     │ (androidx.core.splashscreen on Android, LaunchScreen.storyboard on iOS)
     │ Instant solid background matching launchBackground
     ▼
[Stage 2: Custom HTML Splash WebView]
     │ Renders index.html, CSS animations, and branding in parallel with main app loading
     │
     ▼
[Main Application Ready]
     │ JavaScript calls hideSplash()
     ▼
[Smooth Fade Transition into Main Web UI]
```

### Stage 1: Native OS Launch Background
The operating system immediately displays `launchBackground` before any WebView or JavaScript engine can initialize.

### Stage 2: Custom HTML Splash Screen
A lightweight, dedicated native WebView loads your `splash.source` assets immediately upon shell creation. Because it loads in parallel with the main web application bundle, complex animations or progress bars can play while the main bundle initializes.

## Splash Folder Anatomy

Create a directory containing an `index.html` file alongside any required CSS, images, or fonts:

```text
resources/splash/
├── index.html          # HTML entry point
├── style.css           # Styling and keyframe animations
└── brand-logo.svg      # Vector branding asset
```

### Example `index.html`

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <link rel="stylesheet" href="./style.css" />
  </head>
  <body>
    <div class="splash-container">
      <img src="./brand-logo.svg" alt="Logo" class="logo-pulse" />
      <div class="spinner"></div>
    </div>
  </body>
</html>
```

## Programmatic Dismissal with `hideSplash()`

When using `"dismissOn": "ready"`, call `hideSplash()` from `@wefterjs/core` once your main UI has mounted:

```typescript
import { hideSplash } from "@wefterjs/core";

async function onAppReady() {
  // Perform authentication checks, state hydration, or initial API calls
  await initializeUserData();

  // Dismiss the splash screen with smooth native fade
  await hideSplash();
}
```
