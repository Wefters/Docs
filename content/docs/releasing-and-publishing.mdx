## Overview

A store release is one command once the project is set up:

```bash
wefter build all --release
```

It builds the web app (through your `wefter:build:before` hook), copies it into the native projects, stamps the version, runs the release checks, and produces a signed App Bundle and APK for Android and a signed `.ipa` for iOS in `build/`.

---

## Production Release Workflow

<Steps>
  <Step>
    ### 1. One-time setup A `production` environment, a version, signing for each platform, and a hook that builds the
    web app — see below.
  </Step>
  <Step>### 2. Check readiness `wefter doctor --release-readiness` runs the release checks without building.</Step>
  <Step>
    ### 3. Raise the build number Every upload needs a higher build number: bump `buildNumber`, or pass `--build-number`
    (CI run numbers work well).
  </Step>
  <Step>
    ### 4. Build `wefter build android --release`, `wefter build ios --release`, or `wefter build all --release`.
  </Step>
  <Step>
    ### 5. Upload The `.aab` to the Google Play Console, the `.ipa` to App Store Connect (Transporter or `xcrun
    altool`), and the crash-report files to your crash reporter.
  </Step>
</Steps>

## 1. One-Time Setup

```json title="wefter.config.json"
{
  "version": "1.0.0",
  "buildNumber": 1,
  "environments": {
    "development": { "appId": "com.example.shop.dev", "appName": "Shop (Dev)" },
    "production": { "appId": "com.example.shop", "appName": "Shop" }
  },
  "build": {
    "ios": { "usesNonExemptEncryption": false }
  },
  "signing": {
    "android": {
      "keystorePath": "keys/upload.jks",
      "keyAlias": "upload",
      "storePassword": "${WEFTER_KEYSTORE_PASSWORD}"
    },
    "ios": {
      "teamId": "ABCDE12345"
    }
  }
}
```

```json title="package.json"
{
  "scripts": {
    "wefter:build:before": "vite build --mode $WEFTER_ENV"
  }
}
```

```bash title=".env (gitignored)"
WEFTER_KEYSTORE_PASSWORD=your-keystore-password
```

- **Android signing**: create an upload keystore and keep it out of git — see [Android Signing](/docs/app-configuration/android-signing).
- **iOS signing**: your Team ID is enough on a Mac signed in to Xcode; CI needs an App Store Connect API key — see [iOS Signing](/docs/app-configuration/ios-signing).
- **Versioning**: `version` is what users see; `buildNumber` must go up with every upload — see [Versioning](/cli/build#versioning).

## 2. Pre-Release Verification

```bash
wefter doctor --release-readiness
```

It runs the same checks as `wefter build --release` for both platforms: debug settings, signing and its secrets, app ids, the web app (source maps, development addresses, resources the Content Security Policy blocks), the build number against earlier releases, and the iOS store requirements. Errors fail the check; warnings are listed. See [Release checks](/cli/build#release-checks).

---

## 3. Building

```bash
# Android: signed App Bundle (for Google Play) + APK (for testing)
wefter build android --release

# iOS: signed .ipa for App Store Connect
wefter build ios --release

# Both, with the build number from CI, failing on any warning
wefter build all --release --build-number "$BUILD_NUMBER" --strict
```

```text
build/
  android/production/1.0.0-1/
    Shop-production-1.0.0-1-release.aab
    Shop-production-1.0.0-1-release.apk
    mapping.txt
    build-info.json
  ios/production/1.0.0-1/
    Shop-production-1.0.0-1.ipa
    Shop.dSYM.zip
    build-info.json
```

Keep `mapping.txt`, `native-debug-symbols.zip` and `*.dSYM.zip` with each release: crash reports from release builds are only readable with them. `build-info.json` records the git commit, version and checksums of everything built.

## Release Checklist

| Checkpoint                 | Requirement                                                                | How to verify                               |
| -------------------------- | -------------------------------------------------------------------------- | ------------------------------------------- |
| **Production environment** | Its own `appId` (not the template's, not shared with another environment). | `wefter doctor --release-readiness`         |
| **Version**                | `version` set; `buildNumber` higher than the last upload.                  | Build summary: `Shop 1.4.0 (42)`            |
| **Signing**                | `signing.android` and `signing.ios` complete; secrets in `.env` or CI.     | `wefter doctor --release-readiness`         |
| **Web app**                | No source maps or development addresses; fonts and scripts bundled.        | Release check warnings                      |
| **iOS store**              | Opaque App Store icon, privacy manifest, `usesNonExemptEncryption` set.    | Release check warnings                      |
| **Tested**                 | The release APK installed on a device; the `.ipa` through TestFlight.      | `adb install build/android/…/*.apk`         |
| **Symbols kept**           | `mapping.txt` and dSYMs archived with the release.                         | `build/<platform>/<env>/<version>-<build>/` |
