## Overview

Wefter is an open-source mobile application framework that turns web applications into native Android and iOS applications.

Unlike hybrid frameworks that bundle custom JavaScript runtimes or local HTTP servers, Wefter loads web builds directly into native WebViews (`android.webkit.WebView` and `WKWebView`) and communicates over a low-latency native bridge.

```ts
import { invokeNative } from "@wefterjs/core";

// Asynchronous native method call returning a typed Promise
const result = await invokeNative<{ active: boolean }>(
  "camera",
  "toggleTorch",
  { enable: true },
);
```

## Technical Architecture Breakdown

```text
+-------------------------------------------------------------------+
|                        Web Application UI                         |
|             (Vue, React, Svelte, Angular, Vanilla JS)             |
+-------------------------------------------------------------------+
                                  |
                      invokeNative() / registerHook()
                                  |
+-------------------------------------------------------------------+
|                     Wefter Core Bridge Layer                      |
|                window.AndroidBridge / webkit.messageHandlers      |
+-------------------------------------------------------------------+
                 /                                 \
   Android Bridge Dispatcher                iOS Bridge Dispatcher
 (BridgeDispatcher.kt)                    (BridgeDispatcher.swift)
                |                                   |
   Native Kotlin Plugin                     Native Swift Plugin
(DeviceTelemetryPlugin.kt)                (DeviceTelemetryPlugin.swift)
```

### 1. The Native Bridge Protocol

When JavaScript calls `invokeNative(plugin, method, payload)`:

- On **Android**: Payload JSON is dispatched via `window.AndroidBridge.invoke(callId, plugin, method, payloadJson)`.
- On **iOS**: Payload JSON is dispatched via `window.webkit.messageHandlers.WefterBridge.postMessage({ callId, plugin, method, payload })`.

The native bridge resolves the target plugin instance from `WefterBridge`, invokes the registered dispatcher method (`<PluginName>PluginDispatch`), and settles the JavaScript Promise via `resolve()` or `reject()`.

### 2. High-Performance Codegen (No Reflection)

During [`wefter sync`](/cli/sync), Wefter generates static Kotlin and Swift registry dispatchers (`GeneratedRegistry.kt` and `GeneratedRegistry.swift`). Native method calls are routed directly to annotated functions (`@WefterMethod` in Kotlin, `// @WefterMethod` in Swift) with **zero runtime reflection overhead**.

## Framework Guarantees & Capabilities

1. **Framework Independence**: `@wefterjs/core` exports standalone TypeScript functions (`invokeNative`, `definePlugin`, `registerHook`) compatible with any UI library or framework.
2. **Deterministic Locking (`wefter.lock.json`)**: Every synced plugin version and file hash is recorded in `wefter.lock.json` to prevent environmental drift across team builds.
3. **Environment Scoping**: `wefter.config.json` supports named build environments (`development`, `staging`, `production`), allowing different bundle IDs and app names to co-exist on test devices.
4. **Disposable Native Shells**: `.wefter/native/android` and `.wefter/native/ios` are disposable targets regenerated on `wefter sync`.
5. **Ejection Support**: Developers can run [`wefter eject`](/cli/eject) at any time to convert disposable shells into standard Android Studio and Xcode projects.
