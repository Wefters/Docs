## Architecture & Bridge Performance

<Accordions type="single">
  <Accordion title="Why does Wefter omit a JavaScript interpreter runtime?">
    Wefter intentionally avoids bundling a JavaScript runtime (like V8 or Hermes) or running a local HTTP node server inside mobile applications. Your web application code executes directly inside the native OS WebView (`android.webkit.WebView` and `WKWebView`). Native calls cross a thin, synchronous-to-asynchronous bridge protocol, minimizing application binary size and startup latency.
  </Accordion>

<Accordion title="Can I use React, Svelte, Angular, or SolidJS instead of Vue?">
  Yes. The Wefter runtime (`@wefterjs/core`) is completely framework-agnostic.
  `invokeNative`, `definePlugin`, and `registerHook` are standalone JavaScript
  functions with zero UI framework dependencies. Any web framework capable of
  producing static web builds or serving a local dev server works out of the
  box.
</Accordion>

  <Accordion title="Does the same frontend application code run on both Android and iOS?">
    Yes. Web application code written with `invokeNative` runs identically on Android and iOS without per-platform branching. At runtime, `invokeNative` automatically dispatches calls to whichever native platform bridge (`window.AndroidBridge` or `window.webkit.messageHandlers.WefterBridge`) is active.
  </Accordion>
</Accordions>

## Plugins & Native Code

<Accordions type="single">
  <Accordion title="Why does wefter sync require explicit plugin declarations?">
    Wefter deliberately avoids scanning `node_modules` for implicit native plugins. Plugins must be explicitly added via [`wefter add`](/cli/add) and declared in `wefter.config.json`'s `plugins` array. This prevents unintended third-party dependencies from silently injecting unreviewed native permissions or Kotlin/Swift code into your application.
  </Accordion>

<Accordion title="Must a plugin support both Android and iOS?">
  No. Wefter supports single-platform plugins (`android/` directory only or
  `ios/` directory only). If a web app calls a method on an unsupported platform
  at runtime, `invokeNative` cleanly rejects the Promise with
  `WefterBridgeError` code `"UNKNOWN_PLUGIN"`.
</Accordion>

  <Accordion title="Can I hand-edit files inside .wefter/native/?">
    No. Files inside `.wefter/native/` are disposable and regenerated from scratch on every `wefter sync`. Any manual edits made inside `.wefter/native/` will be overwritten. If you need to permanently customize native project files, run [`wefter eject`](/cli/eject) to turn the project into standard permanent `android/` and `ios/` folders.
  </Accordion>
</Accordions>

## Development Workflow & Security

<Accordions type="single">
  <Accordion title="How does live hot-reload work with wefter run --watch?">
    When running `wefter run <platform> --watch`, Wefter launches the native app shell and configures the WebView to point at your local web dev server URL instead of local static assets. Web UI changes reload instantaneously without requiring native recompilation. Native Kotlin/Swift code changes require running `wefter sync`.
  </Accordion>

<Accordion title="Do I need a Mac to build Android applications?">
  No. Building Android APKs requires Node.js, JDK 17, and the Android SDK, all
  of which run on Linux, macOS, and Windows. A Mac is only required when
  compiling iOS application bundles (`.app`) or running iOS Simulators via
  Xcode.
</Accordion>

  <Accordion title="What security auditing does wefter plugin validate perform?">
    [`wefter plugin validate`](/cli/plugin-validate) checks `plugin.json` schemas, verifies `@WefterMethod` parameter signatures, and ensures dangerous Android permissions contain `"PERMISSION_DENIED"` error handling. It validates structural correctness, but does not substitute for reviewing third-party native code before adding it to production apps.
  </Accordion>
</Accordions>
