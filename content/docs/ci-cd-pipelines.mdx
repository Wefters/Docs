## Overview

`wefter build` is made for CI: signing values come from environment variables, the build number can come from the pipeline, `--strict` fails the job on any release warning, and `--json` prints a machine-readable result. The built files land in `build/` with a `build-info.json` and checksums, ready to upload.

The examples assume the web app is built by a `wefter:build:before` hook:

```json title="package.json"
{
  "scripts": {
    "wefter:build:before": "vite build --mode $WEFTER_ENV"
  }
}
```

## 1. GitHub Actions: Android App Bundle

`wefter.config.json` reads the passwords from the environment:

```json
{
  "signing": {
    "android": {
      "keystorePath": "keys/upload.jks",
      "keyAlias": "upload",
      "storePassword": "${WEFTER_KEYSTORE_PASSWORD}"
    }
  }
}
```

```yaml title=".github/workflows/android-release.yml"
name: Android Release

on:
  push:
    tags: ["v*"]

jobs:
  android:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm
      - run: pnpm install --frozen-lockfile

      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: "17"
      - uses: android-actions/setup-android@v3

      - name: Restore the upload keystore
        run: |
          mkdir -p keys
          echo "${{ secrets.ANDROID_KEYSTORE_BASE64 }}" | base64 -d > keys/upload.jks

      - name: Build signed App Bundle and APK
        env:
          WEFTER_KEYSTORE_PASSWORD: ${{ secrets.WEFTER_KEYSTORE_PASSWORD }}
        run: npx wefter build android --release --build-number "${{ github.run_number }}" --strict --json > build-result.json

      - uses: actions/upload-artifact@v4
        with:
          name: android-release
          path: build/android/production/
```

`--strict` fails the job on any release check warning (for example a source map left in the web app). `build-result.json` lists every file with its path, size and SHA-256.

## 2. GitHub Actions: iOS `.ipa`

A CI runner has no Xcode account, so iOS signing uses an App Store Connect API key (see [iOS Signing](/docs/app-configuration/ios-signing#automatic-signing-in-ci-app-store-connect-api-key)):

```json
{
  "signing": {
    "ios": {
      "teamId": "ABCDE12345",
      "appStoreConnect": {
        "keyPath": "keys/AuthKey.p8",
        "keyId": "${WEFTER_ASC_KEY_ID}",
        "issuerId": "${WEFTER_ASC_ISSUER_ID}"
      }
    }
  }
}
```

```yaml title=".github/workflows/ios-release.yml"
name: iOS Release

on:
  push:
    tags: ["v*"]

jobs:
  ios:
    runs-on: macos-15
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm
      - run: pnpm install --frozen-lockfile

      - name: Restore the App Store Connect key
        run: |
          mkdir -p keys
          echo "${{ secrets.ASC_KEY_BASE64 }}" | base64 -d > keys/AuthKey.p8

      - name: Build signed .ipa
        env:
          WEFTER_ASC_KEY_ID: ${{ secrets.ASC_KEY_ID }}
          WEFTER_ASC_ISSUER_ID: ${{ secrets.ASC_ISSUER_ID }}
        run: npx wefter build ios --release --build-number "${{ github.run_number }}" --strict

      - name: Upload to App Store Connect
        env:
          ASC_KEY_ID: ${{ secrets.ASC_KEY_ID }}
          ASC_ISSUER_ID: ${{ secrets.ASC_ISSUER_ID }}
        run: |
          mkdir -p ~/.appstoreconnect/private_keys
          cp keys/AuthKey.p8 ~/.appstoreconnect/private_keys/AuthKey_${ASC_KEY_ID}.p8
          xcrun altool --upload-app --type ios \
            --file build/ios/production/*/*.ipa \
            --apiKey "$ASC_KEY_ID" --apiIssuer "$ASC_ISSUER_ID"
```

## 3. Uploading from a Hook

Instead of separate CI steps, a `wefter:build:after` hook can upload what was built — it gets the paths in `WEFTER_ARTIFACT` and `WEFTER_ARTIFACTS` — and `wefter:build:failed` can notify your team. See [Hooks](/cli/hooks#example-2-uploading-build-artifacts).

## 4. Fastlane

Fastlane can upload the files `wefter build` produced:

```ruby
platform :android do
  lane :internal do
    sh("npx wefter build android --release --format aab")
    upload_to_play_store(
      track: "internal",
      aab: Dir["../build/android/production/*/*-release.aab"].max_by { |f| File.mtime(f) }
    )
  end
end

platform :ios do
  lane :beta do
    sh("npx wefter build ios --release")
    upload_to_testflight(
      ipa: Dir["../build/ios/production/*/*.ipa"].max_by { |f| File.mtime(f) }
    )
  end
end
```

## Secrets Checklist

| Secret                         | Platform | Used for                                                                       |
| ------------------------------ | -------- | ------------------------------------------------------------------------------ |
| `ANDROID_KEYSTORE_BASE64`      | Android  | The upload keystore, base64-encoded.                                           |
| `WEFTER_KEYSTORE_PASSWORD`     | Android  | The keystore password (and key password, unless `WEFTER_KEY_PASSWORD` is set). |
| `WEFTER_KEY_PASSWORD`          | Android  | The key password, when it differs from the keystore's.                         |
| `ASC_KEY_BASE64`               | iOS      | The App Store Connect API key (`.p8`), base64-encoded.                         |
| `ASC_KEY_ID` / `ASC_ISSUER_ID` | iOS      | The key's ID and issuer, for signing and uploading.                            |
