## Overview

Operating system permissions are required before plugins can access sensitive hardware (camera, geolocation, contacts, bluetooth, microphone, photo library).

- **Android**: Runtime permissions must be declared in `plugin.json` (`permissions.android`) and checked/requested dynamically using `hasPermission()` and `requestPermission()`.
- **iOS**: Privacy usage descriptions must be declared in `plugin.json` (`permissions.ios`) and requested using Apple framework APIs (`AVCaptureDevice`, `CLLocationManager`, `PHPhotoLibrary`).

---

## Android Permission Flow

Android requires a 2-step permission handling pattern:

1. **Manifest Declaration**: List permissions in `plugin.json` (`permissions.android`).
2. **Runtime Check & Request**: Check `hasPermission()` before requesting `requestPermission()`.

### Android Implementation Example

```kotlin
package dev.wefter.bridge

import android.Manifest
import android.content.Context
import org.json.JSONObject

class CameraPlugin(context: Context, dispatcher: BridgeDispatcher) : WefterPlugin(context, dispatcher) {

    @WefterMethod
    fun open(payload: JSONObject, callback: (Result<Any>) -> Unit) {
        // Step 1: Check if permission is already granted
        if (hasPermission(Manifest.permission.CAMERA)) {
            startCamera(callback)
            return
        }

        // Step 2: Request runtime permission
        requestPermission(activity, Manifest.permission.CAMERA) { granted ->
            if (granted) {
                startCamera(callback)
            } else {
                reject(callback, "PERMISSION_DENIED", "Camera permission was denied")
            }
        }
    }

    private fun startCamera(callback: (Result<Any>) -> Unit) {
        resolve(callback, JSONObject().put("active", true))
    }
}
```

<Callout type="info">
  **Audit Enforcement**: If a plugin declares dangerous Android permissions (such as `CAMERA`, `ACCESS_FINE_LOCATION`,
  `RECORD_AUDIO`, `READ_CONTACTS`), `wefter plugin validate` verifies that Kotlin code contains explicit
  `"PERMISSION_DENIED"` error handling.
</Callout>

## iOS Permission Flow

iOS permission handling relies on framework-specific APIs and mandatory `Info.plist` usage description strings.

### iOS Implementation Example

```swift
import Foundation
import AVFoundation

final class CameraPlugin: WefterPlugin {

    // @WefterMethod
    func open(payload: [String: Any], callback: @escaping (Result<Any, Error>) -> Void) throws {
        switch AVCaptureDevice.authorizationStatus(for: .video) {
        case .authorized:
            startCamera(callback)

        case .notDetermined:
            AVCaptureDevice.requestAccess(for: .video) { [weak self] granted in
                DispatchQueue.main.async {
                    if granted {
                        self?.startCamera(callback)
                    } else {
                        self?.reject(callback, code: "PERMISSION_DENIED", message: "Camera permission was denied")
                    }
                }
            }

        case .denied, .restricted:
            reject(callback, code: "PERMISSION_DENIED", message: "Camera permission was denied")

        @unknown default:
            reject(callback, code: "PERMISSION_DENIED", message: "Camera permission was denied")
        }
    }

    private func startCamera(_ callback: (Result<Any, Error>) -> Void) {
        resolve(callback, data: ["active": true])
    }
}
```

## The iOS Permission Crash Hazard

<Callout type="warn">
  **Fatal iOS App Termination**: Calling an iOS framework permission API (such as `AVCaptureDevice.requestAccess`) when
  the required usage description key (e.g. `NSCameraUsageDescription`) is missing from `Info.plist` will **immediately
  crash the entire application process**. It cannot be caught by Swift `do/catch` blocks.
</Callout>

### How Wefter Protects Your Application

During [`wefter build ios`](/cli/build) and [`wefter run ios`](/cli/run), Wefter performs an automated `Info.plist` audit check (`checkInfoPlistPermissionKeys`).

If a plugin requests native permissions but its required `Info.plist` key is missing, `wefter build` halts before invoking `xcodebuild`:

```text
[ERROR] iOS permission configuration check failed:
  - Missing "NSCameraUsageDescription" in Info.plist, required by plugin "@wefterjs/camera" — calling this permission's API will CRASH the app immediately. Run `wefter sync` to regenerate Info.plist.
```
