## Overview

Testing a Wefter native plugin requires a 2-tier testing strategy:

- **Tier 1: JS Client Mock Testing**: Testing the TypeScript wrapper (`src/index.ts`) using `@wefterjs/core/testing` in Vitest or Jest (no native device required).
- **Tier 2: Real Native On-Device Testing**: Verifying native Kotlin and Swift code on physical Android ADB devices and iOS Simulators.

---

## Tier 1: JS Client Mock Testing (`@wefterjs/core/testing`)

`@wefterjs/core/testing` provides `installMockBridge` and `uninstallMockBridge` to simulate native bridge responses in unit testing environments:

```ts
// @vitest-environment jsdom
import { afterEach, describe, expect, it } from "vitest";
import { installMockBridge, uninstallMockBridge } from "@wefterjs/core/testing";
import { Scanner } from "../src/index.js";

describe("Scanner Plugin JS Wrapper", () => {
  afterEach(() => {
    uninstallMockBridge();
  });

  it("resolves successfully when mock bridge returns data", async () => {
    installMockBridge({
      scanner: (method, payload) => {
        if (method === "scan") return { code: "12345" };
        throw new Error(`Unmocked method ${method}`);
      },
    });

    const result = await Scanner.scan();
    expect(result).toEqual({ code: "12345" });
  });

  it("handles permission denial error rejection", async () => {
    installMockBridge({
      scanner: () => {
        throw new Error("Camera permission denied");
      },
    });

    await expect(Scanner.scan()).rejects.toMatchObject({
      code: "MOCK_ERROR",
      message: "Camera permission denied",
    });
  });
});
```

## Tier 2: Real Native On-Device Integration Testing

<Callout type="warn">
  **Mock Tests Are Not Enough**: Unit tests verify your TypeScript client
  wrapper, but cannot verify whether native Kotlin/Swift code compiles, whether
  permission prompts show on OS devices, or whether `plugin.json` permissions
  match native code requirements.
</Callout>

### Integration Testing Workflow

1. **Link/Add Plugin**: Add your plugin package to a test Wefter application using [`wefter add`](/cli/add).
2. **Sync Native Projects**: Run [`wefter sync`](/cli/sync) to weave native Kotlin/Swift code into native shells.
3. **Execute Live Testing**:
   - **Android**: Run `wefter run android --watch` on a connected ADB device or emulator.
   - **iOS**: Run `wefter run ios --watch` on an iOS Simulator.
4. **Audit Both Paths**: Test both **permission granted** and **permission denied** paths on a fresh device instance.
