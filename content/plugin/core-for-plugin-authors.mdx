## Overview

The `@wefterjs/core` package provides the client-side JavaScript runtime API for authoring Wefter native plugin client wrappers (`src/index.ts`).

Plugin authors use `@wefterjs/core` functions to define typed plugin objects (`definePlugin`), invoke native plugin methods (`invokeNative`), and expose event subscription methods (`registerHook`).

---

## Core Client APIs Summary

| Function       | Signature                                            | Purpose                                                                                              |
| -------------- | ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `definePlugin` | `definePlugin<T>(pluginName, methodMap)`             | Utility that generates typed request/response plugin object wrappers automatically.                  |
| `invokeNative` | `invokeNative<T>(plugin, method, payload, options?)` | Low-level function that invokes a native plugin method and returns a typed Promise.                  |
| `registerHook` | `registerHook(hookName, callback)`                   | Subscribes a JavaScript callback to native event streams (`emit`). Returns `{ remove: () => void }`. |

---

## 1. Automatic Type Wrappers: `definePlugin`

For plugins that expose request/response methods, `definePlugin` generates a strongly typed object wrapper automatically:

```ts
import { definePlugin } from "@wefterjs/core";

export interface SensorReading {
  value: number;
}

export interface SensorPluginInterface {
  read(): Promise<SensorReading>;
  reset(): Promise<{ ok: boolean }>;
}

export const Sensor = definePlugin<SensorPluginInterface>("sensor", {
  read: true,
  reset: true,
});
```

### How `definePlugin` Works

`definePlugin` returns an object where each key maps to an asynchronous function calling `invokeNative("sensor", methodName, payload)`.

## 2. Real-Time Event Subscriptions: `registerHook`

If a native plugin pushes real-time event streams (e.g. sensor ticks, barcode scans, location updates), expose a subscription method using `registerHook`:

```ts
import { definePlugin, registerHook } from "@wefterjs/core";

export interface SensorReading {
  value: number;
}

export interface SensorEvent {
  timestamp: number;
  value: number;
}

export const Sensor = {
  ...definePlugin<{ read(): Promise<SensorReading> }>("sensor", { read: true }),

  onReading(callback: (data: SensorEvent) => void): { remove(): void } {
    return registerHook("reading", callback as (data: unknown) => void);
  },
};
```

## 3. Custom Invocation & Timeout Control: `invokeNative`

When your plugin requires custom payload transformation, cancellation (`AbortSignal`), or custom timeouts (`timeoutMs`), call `invokeNative` directly:

```ts
import { invokeNative } from "@wefterjs/core";

export interface ScanOptions {
  timeoutMs?: number;
  signal?: AbortSignal;
}

export const Scanner = {
  scan(options: ScanOptions = {}): Promise<{ code: string }> {
    return invokeNative<{ code: string }>(
      "scanner",
      "scan",
      {},
      {
        timeoutMs: options.timeoutMs,
        signal: options.signal,
      },
    );
  },
};
```

---

## Error Pass-Through

Rejections from `invokeNative` automatically propagate as [`WefterBridgeError`](/plugin/structured-errors) instances. Plugin wrappers should allow native bridge errors to pass through cleanly to callers.
