## Overview

The `@WefterHook` annotation subscribes a native plugin method to internal native-to-native signals dispatched by the host application shell (`BridgeDispatcher`).

Unlike `emit()`, which pushes real-time event streams from native plugins to JavaScript, `@WefterHook` operates entirely within native code with zero JavaScript involvement or payload data overhead.

---

## Method Signatures

`@WefterHook` methods must take zero parameters and return `Unit` (Kotlin) or `Void` (Swift).

### Kotlin (Android)

```kotlin
package dev.wefter.bridge

import android.content.Context

class CameraPlugin(context: Context, dispatcher: BridgeDispatcher) : WefterPlugin(context, dispatcher) {

    @WefterHook("appReady")
    fun onAppReady() {
        // Prepare native camera hardware when web app completes initial load
    }
}
```

### Swift (iOS)

```swift
import Foundation

final class CameraPlugin: WefterPlugin {

    // @WefterHook("appReady")
    func onAppReady() {
        // Prepare native camera hardware when web app completes initial load
    }
}
```

## Registry Generation & Dispatching

During [`wefter sync`](/cli/sync), Wefter extracts methods annotated with `@WefterHook("<name>")` and generates registration code inside `WefterPluginRegistry`:

```kotlin
// Generated Kotlin Registry
dispatcher.subscribeHook("appReady") { pluginInstance.onAppReady() }
```

When native application shells execute `dispatcher.dispatchHook("appReady")`, all subscribed plugin hook methods execute synchronously.

---

## Active Host Shell Hook Signals

The Wefter native application shells dispatch two built-in lifecycle hook signals:

| Hook Name      | Dispatch Source                                                                                                                  | Purpose                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `"appReady"`   | `WebView` initial page load completion (`onPageFinished` / `didFinishNavigation`) or `invokeNative("__system", "appReady", {})`. | Signals that the web app has completed DOM rendering and bridge initialization.   |
| `"hideSplash"` | `hideSplash()` call from `@wefterjs/core` (`invokeNative("__system", "hideSplash", {})`).                                        | Signals that the web app has explicitly requested native splash screen dismissal. |

---

## Validation Rules

`wefter plugin validate` verifies that every `@WefterHook` declaration includes a valid string name argument and a zero-parameter function body.

If a method signature includes parameters or malformed syntax, validation fails with:

```text
[ERROR] Malformed @WefterHook signature at line <n> (android/ / ios/)
```
