## Overview

When a native plugin call fails, the native layer rejects the execution with a structured error payload containing an error `code` and descriptive `message`.

On JavaScript's side, `invokeNative` catches native rejections and throws a standard `WefterBridgeError` instance.

---

## Standard Error Codes Reference

The following table lists core error codes exported by `WefterErrorCode` (`@wefterjs/core`):

| Error Code            | Origin             | Description                                                                  | Plugin Author Best Practice                                                      |
| --------------------- | ------------------ | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `"TIMEOUT"`           | `@wefterjs/core`   | Call exceeded caller's `timeoutMs` limit (defaults to 10s).                  | Optimize long-running native tasks or move them to event streams (`emit`).       |
| `"ABORTED"`           | `@wefterjs/core`   | Call was cancelled by caller's `AbortSignal`.                                | Clean up native task when cancellation is triggered.                             |
| `"NO_BRIDGE"`         | `@wefterjs/core`   | Web app running outside native WebView environment (browser tab).            | Test for native bridge using `isNativeBridgeAvailable()`.                        |
| `"UNKNOWN_PLUGIN"`    | `BridgeDispatcher` | Requested plugin is not declared in `wefter.config.json` or native registry. | Verify plugin package name is listed in `plugins` array.                         |
| `"UNKNOWN_METHOD"`    | `BridgeDispatcher` | Requested method is not registered on native plugin class.                   | Verify `@WefterMethod` spelling and `plugin.json` method declaration.            |
| `"PLUGIN_THREW"`      | `BridgeDispatcher` | Native code threw an unhandled runtime exception.                            | Catch exceptions inside native method and call `reject()` explicitly.            |
| `"PERMISSION_DENIED"` | Native Plugin      | Required Android or iOS permission was denied by user.                       | Call `reject(callback, "PERMISSION_DENIED", "...")` when permission check fails. |
| `"UNKNOWN"`           | Either             | General catch-all error code.                                                | Avoid generic errors; return specific custom error codes.                        |

## Returning Errors from Native Code

### Kotlin (Android)

In Kotlin, call `reject(callback, code, message)` or throw `WefterError`:

```kotlin
package dev.wefter.bridge

import org.json.JSONObject

class StoragePlugin(context: Context, dispatcher: BridgeDispatcher) : WefterPlugin(context, dispatcher) {

    @WefterMethod
    fun write(payload: JSONObject, callback: (Result<Any>) -> Unit) {
        val key = payload.optString("key")
        if (key.isEmpty()) {
            reject(callback, "INVALID_KEY", "Key parameter must be non-empty")
            return
        }

        // Alternative: throw WefterError (caught by dispatcher)
        // throw WefterError("STORAGE_FULL", "Insufficient disk space")
    }
}
```

### Swift (iOS)

In Swift, call `resolve`/`reject` or throw a custom `WefterError`:

```swift
import Foundation

final class StoragePlugin: WefterPlugin {

    // @WefterMethod
    func write(payload: [String: Any], callback: @escaping (Result<Any, Error>) -> Void) throws {
        guard let key = payload["key"] as? String, !key.isEmpty else {
            reject(callback, code: "INVALID_KEY", message: "Key parameter must be non-empty")
            return
        }

        // Alternative: throw custom WefterError
        // throw WefterError(code: "STORAGE_FULL", message: "Insufficient disk space")
    }
}
```

## Swift Runtime Traps vs Exception Safety

<Callout type="warn">
  **Swift Trap Warning**: Swift's `do/catch` statement catches thrown `Error` instances, but **cannot** catch runtime
  fatal traps (such as force-unwrapping `nil` values using `!` or accessing out-of-bounds array indices). Swift fatal
  traps terminate the application process immediately.
</Callout>

### Best Practice Rules for Swift Plugin Authors

1. **Never Force-Unwrap (`!`)**: Use `guard let` or `if let` optional binding.
2. **Never Direct Subscript Without Bounds Check**: Validate dictionary values before casting.
3. **Use Default Fallbacks**: Cast payload arguments safely using `as? String ?? ""`.
